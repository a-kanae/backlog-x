# backlog-x

Backlog の課題・コメント・Wiki・ドキュメント・添付ファイルを**公式 API で取り込み**、手元のブラウザに保存して日本語全文検索つきで閲覧できる、読み取り専用のビューアです。

> **非公式ツールです。** 株式会社ヌーラボとは無関係の個人プロジェクトで、同社が提供・保証・推奨するものではありません。「Backlog」は同社の登録商標です。本ツールは閲覧専用のビューアであり、Backlog の代替・複製ではありません。

## 使い方

### まず試す（Backlog のアカウント不要）

<https://backlog-x-prd.web.app> を開いて「サンプルデータで試す」を押すと、同梱のサンプル（架空のプロジェクト・課題 60 件・コメント 212 件・Wiki 6 ページ）を読み込みます。一覧・全文検索・課題詳細・Backlog 記法の表示をそのまま触れます。API キーもアカウントも要りません。

サンプルの中身はすべて架空です。読み込んだデータもこのブラウザの中だけに保存されます。

### 自分のデータを取り込む

使う方法は 2 つあります。

- **用意してあるサイトを開く** — <https://backlog-x-prd.web.app>（インストール不要）
- **自分で動かす** — このリポジトリを clone して、ローカルで起動するか自分でホスティングする（[後述](#自分でホストする)）

あとは Backlog の API キー（個人設定 → API で発行）とスペース URL を入力して取り込むだけです。取り込み方法は 3 つあります。

| 方法                 | 用途                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| Backlog API から     | 自分の API キーで直接取り込む                                            |
| Backlog ダンプから   | API の生レスポンスを保存したファイルから取り込む（API キー不要で配れる） |
| backlog-x ダンプから | backlog-x が書き出した `.json.gz` から取り込む                           |

取り込み後はオフラインでも動きます。プロジェクト単位で `.json.gz` に書き出せるので、他の人に渡せば同じアーカイブを再現できます。

## セキュリティ

取り込んだデータも API キーも、あなたのブラウザ（IndexedDB / OPFS）の中だけにあります。サーバーへ送る仕組みがそもそもありません。アクセス解析の類も入れていません。

さらに CSP で接続先を Backlog のドメインに限定しているので、**送らないよう実装している**のではなく**送れません**。DevTools の Console で確認できます。

```js
await fetch("https://example.backlog.jp/api/v2/space").catch((e) => e.message); // 通る
await fetch("https://www.google-analytics.com/collect").catch((e) => e.message); // CSP がブロックする
```

なお、**一部のユーザーアイコンは取得できず、Console に CSP 違反として記録されます**。Backlog がアイコンを外部ホストへリダイレクトするためで、**送信がブロックされたのではなく取得に失敗した**ものです。その場合はイニシャル表示になります（全員のアイコンを揃えるには `scripts/fetch-icons.mjs` を使ってください）。

## できること / できないこと

**できること**

- 課題・コメント・Wiki・ドキュメント・添付ファイル・投稿者・日時の取り込み（レート制限を遵守。中断しても再開できます）
- 日本語の全文検索（形態素解析つき）
- URL で課題を直接指す（`/projects/123/issues/456`）
- Backlog 記法のレンダリング（メンション・課題リンク・埋め込み画像）
- `.json.gz` での書き出しと受け渡し

**できないこと**

- **編集全般**（作成・更新・削除）
- 複数ユーザーでのログインや中央共有（サーバーを持たないため。共有はファイルの受け渡しで行います）

## 自分でホストする

```bash
npm install
npm run build   # out/ に静的ファイルが出力される
```

サーバーは不要です。`out/` を静的ホスティングに置くだけで動きます。

**ただし rewrites を設定できるホスティングが必要です**（Firebase Hosting / Cloudflare Pages / Netlify 等）。課題を URL で直接指せる形を保つため、実 URL を静的シェルへ流す設定を使っています。素の GitHub Pages では `/projects/123` への直アクセスが 404 になります。

Firebase Hosting なら `firebase.json` を用意済みです（rewrites と CSP を含む）。`.firebaserc.example` を `.firebaserc` にコピーして自分のプロジェクト ID を書くか、`firebase use --add` で紐付けてください。

```bash
npm run build
firebase deploy --only hosting
```

**他のホスティングを使う場合は、`firebase.json` の `headers` にある CSP を移してください。** 無くても動きますが、上に書いた「送れない」ことの裏付けが失われます。

## 開発者向け

```bash
npm install
npm run dev   # http://localhost:3000
```

Next.js / IndexedDB + OPFS / flexsearch + kuromoji で作っています。開発は dev サーバーを使ってください（`output: 'export'` は dev では無効化され、動的ルートに実 ID で直接アクセスできます）。

デモ用のサンプルデータは生成スクリプトで作り直せます。出力先は `public/sample/` で、中身は Backlog API のレスポンスと同じ形（ダンプ形式）なので、取り込みは通常の経路をそのまま通ります。

```bash
npm run sample
```

このリポジトリの Next.js は破壊的変更を含むバージョンです。コードを書く前に `node_modules/next/dist/docs/` を参照してください（`AGENTS.md` 参照）。
